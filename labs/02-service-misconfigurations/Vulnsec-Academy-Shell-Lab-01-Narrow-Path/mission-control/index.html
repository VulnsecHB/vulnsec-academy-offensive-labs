01

ENUMERATE THE SHELL

Do not assume which cage you are in.

SSH only gives a prompt. Print $0, $SHELL, and $PATH. Try cd / and a command that contains a slash. A private PATH, a refused cd, and “cannot specify / in command names” is restricted bash — not a broken install. The user flag is already in home.

echo $0 $SHELLNames the login shell
echo $PATH && ls binEvery binary you are allowed
cd /Refused — confirms the cage
02

GTFOBINS ESCAPE

Look up every allowed binary.

Open gtfobins.github.io and search the allow-list one name at a time. ls, cat, echo, pwd, date and whoami have no shell escape that helps inside rbash. find does — GTFOBins → find → Shell. After that, this shell still inherited the tiny PATH, so reset it before you try sudo.

findGTFOBins → Shell
-exec /bin/bashLeaves rbash
export PATH=...Unhides sudo, env, id
03

PRIVILEGE ESCALATION

Enumerate sudo the same way.

Do not hunt random SUID binaries first. Ask sudo what this account may run. sudo -l returns a single NOPASSWD path: /usr/bin/env. GTFOBins → env → Sudo is a root shell. Then read /root/root.txt.

sudo -lDo not skip this — it names the binary
gtfobins / envSudo function is a root shell
/root/root.txtSecond flag
